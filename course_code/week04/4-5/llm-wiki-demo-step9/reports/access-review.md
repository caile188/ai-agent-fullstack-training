## 1. 逐项审查

### 1.1 来源读取是否检查身份？

**答：不检查。标为「未实现」。**

- **机制层面**：读取 `raw/` 完全由 OS 文件模式决定。**没有**任何代码、钩子或中间件
  在读取路径上做身份判断。schema 第 8 条说"鉴权由宿主程序执行"——
  但**本项目里那个"宿主程序"并不存在**；这句话是**规则声明**，不是已实现的机制。
- **实际唯一的"限制"**：33 个文件中有 **10 个是 `0600`**（仅属主可读），
  其余 **23 个是 `0644`**（所有本地用户可读）。
- **但这个限制不构成权限模型**，理由有三：
  1. **它只区分"属主 vs 其他"，没有"授权身份"概念** —— 无法表达"认证组可读、支付组不可读"。
  2. **本机只有一个身份**（`wilson`），而 `wilson` 就是全部文件的属主 →
     **任何"未授权身份"都读不到任何东西，"授权身份"能读到全部东西**。
     这不是隔离，是单用户系统。
  3. **该限制的分布不一致**（见 §1.2），看起来是导入产生的**副产物**，不是有意的策略。

> 观察记录：本次审查**以属主 `wilson` 身份**读取过 `0600` 文件（如 `raw/v1/app/auth.py`）。
> **这属于 owner 访问，不构成任何授权测试**，不能作为"鉴权通过"的证据。

### 1.2 生成页面的可见范围由谁确定？

**答：无人确定。标为「未实现」。**

- **没有任何机制设置派生页面的可见范围。** 页面只是文件被 `cp` 到 `wiki/`，
  继承当时的 umask，**不与来源的可见范围联动**。
- **具体不一致（重要）**：

  | 类别 | 模式 | 数量 | 说明 |
  | --- | --- | --- | --- |
  | `raw/v1` 来源 | `0600` | 10 | 含 `app/auth.py`（硬编码密钥）、`app/session.py`（TTL 常量）等 |
  | `raw/v1` 来源 | `0644` | 2 | `docs/testing-guide.md`、`pdf/PRD-login-2.5.0.pdf` |
  | `raw/v2` 当前规则 | `0644` | 1 | `docs/session-rules.md` |
  | `raw/discussions` | `0644` | 1 | `ttl-proposal.md` |
  | **全部派生页面** | `0644` | 5 | `wiki/**` 5 个页面**全部**世界可读 |
  | manifests / schema / reports / staging | `0644` | 15 | 全部世界可读 |

- **后果**：最敏感的源码（`auth.py` 的 `_SECRET`）在源头上是 `0600`，
  但**引用并讨论它的知识页是 `0644`**。也就是说：
  **来源受限、派生不受限 —— 限制没有向下游传播。**
  任何能读 `wiki/` 的本地用户，都能读到关于受限来源的内容（含其位置与取值描述）。
- **谁"确定"可见范围**：实际操作上是 **OS 默认 umask**，没有任何人做策略决定。

### 1.3 发布是否检查访问策略？

**答：不检查。标为「未实现」。**

- 发布动作是人工 `cp staging/... wiki/...`，日志自述"逐文件 `cp`，非事务性"。
- 发布前**没有**任何策略判定环节：
  - 不检查"谁"在发布（无身份参数）
  - 不检查"要发布的页面是否允许对某身份可见"（无策略文件）
  - 不检查来源的可见范围是否应传递到页面（无传播逻辑）
- `reports/prepublish.md` 做的是**结构检查与内容核对**（哈希、引用、断言有无依据），
  **不涉及访问策略**。二者不可混淆。

### 1.4 索引、摘要、文件读取、导出是否执行相同限制？

**答：它们没有任何"限制"可言，因此谈不上"相同"。标为「未实现」。**

| 通道 | 是否施加访问限制 | 实际行为 |
| --- | --- | --- |
| **文件读取** | 仅 OS 模式位 | 属主可读全部；无身份判断 |
| **索引 `wiki/index.md`** | **无** | `0644`，含全部页面标题 + 摘要 + 来源清单 + 缺口清单 |
| **摘要（页面内）** | **无** | `0644`；摘要与正文同等可读 |
| **导出** | **无** | 无导出程序；`cp`/`tar` 在 OS 层直接复制，**必然绕过任何（不存在的）策略** |

- **关键点**：索引与摘要**不是受限视图**。因为没有策略层，
  索引里能看到的与正文里能看到的**完全一致**，
  **不存在"索引脱敏、正文受限"或反之的机制**。
- **旁路**：由于 `raw/` 的 `0600` 只挡"其他用户"，
  而 `wiki/` 全是 `0644`，**索引实际上成了受限来源内容的无限制广播面**。

### 1.5 来源撤权后，依赖页和缓存怎样处理？

**答：无任何处理机制。标为「未实现」。**

- **依赖页**：`staging/dependencies.json` 记录了页面依赖哪些来源，
  但**仅用于影响分析（人工/模型驱动）**，**不是访问控制**。
  若某来源被撤权，**不会**自动发生以下任何事：
  - 不会自动下架或降级依赖它的页面
  - 不会自动重新计算页面可见范围
  - 不会自动通知或阻断
- **缓存**：**本项目没有缓存层**（无页面缓存、无 CDN、无查询缓存）。
  所以"撤权后缓存如何处理"**不适用** —— 不是"处理得好"，而是**没有缓存**。
- **向量索引**：**未接入**。不存在 embedding / 向量库，故**无需重嵌入**。
- **需注意的额外位置（潜在影子副本）**：
  父目录存在 `../llm-wiki-demo.tgz`（`117926` 字节，`0644`）。
  该归档**很可能包含全部内容**（含 `0600` 来源的副本），
  **但归档本身是 `0644`** —— 若属实，则 `0600` 限制被该归档整体绕过。
  **本次未解包核实**（按指示不做解包探查），故**仅登记为待核实的泄露面**，不作结论。
- **撤权在 OS 层的实际效果**：只能靠 `chmod` / `mv` / `rm` 手工操作，
  **无审计、无留痕、无回滚**（非 git 仓库）。

## 2. 结论：是否存在"可执行权限控制"？

**不存在。** 因此按指示：

- **授权身份 vs 未授权身份的双身份读取测试：无法执行，未执行。**
  本机只有 `wilson` 一个身份，且它是全部文件的属主。
  **不伪造任何允许/拒绝结果。**
- **"模型遵守提示词"不计入权限隔离通过。** schema 第 8 条的约束是**提示词层面的自律**，
  它约束的是模型行为，**不构成访问控制**。即便模型 100% 遵守，
  任何绕过模型的直接文件读取（`cat`、`cp`、Finder、`tar`）都**不受任何约束**。
  故本实验的权限边界**不通过**。

## 3. 最小接入位置（建议，本次不实施）

若要让本实验具备**最小可执行**的权限边界，需在以下三处各加一个检查点。
注意：**这些目前都不存在**。

| # | 接入位置 | 现状 | 最小改动 |
| --- | --- | --- | --- |
| 1 | **策略定义** | 无 | 新增 `manifests/access-policy.json`：`source/page → allowed_identities` 映射。这是**唯一权威**策略源 |
| 2 | **读取闸口** | 无读取程序 | 新增唯一读取函数（如 `read_artifact(path, identity)`），所有读取（含索引/摘要生成）**必须**经它；直接 `open()` 视为绕过 |
| 3 | **发布闸口** | 人工 `cp` | 将 `cp` 包装为 `publish(page, identity)`：先查策略、校验身份，再落盘并写审计行 |
| 4 | **导出闸口** | 无 | 导出必须经策略过滤；同时**处理归档面**（`llm-wiki-demo.tgz` 等），否则闸口形同虚设 |
| 5 | **撤权响应** | 无 | 撤权时按 `dependencies.json` 计算受影响页面集，降级其可见范围并登记；**无缓存可失效**，但需处理归档与影子副本 |

**验收用例（建议，尚未执行 —— 无机制可跑）**：

```
AC-1 授权身份读受限来源     → 期望 允许；实际 未执行（无机制）
AC-2 未授权身份读同一来源   → 期望 拒绝；实际 未执行（无机制，且无第二身份可测）
AC-3 未授权身份读派生页     → 期望 拒绝；实际 未执行
AC-4 未授权身份读索引摘要   → 期望 拒绝；实际 未执行（索引当前为 0644）
AC-5 未授权身份导出/打包    → 期望 拒绝；实际 未执行
AC-6 撤权后依赖页可见性降级 → 期望 生效；实际 未执行（无传播逻辑）
AC-7 撤权后归档/影子副本    → 期望 同步收口；实际 未执行
```

> 上述"实际"列**一律为「未执行」**，因为不存在可执行机制。
> **不填写 PASS / FAIL** —— 那需要真实机制与真实第二身份。

## 6. 能力边界声明（须如实说明）

- **无可执行权限控制** —— 本实验的权限边界**不通过**。
- **无非 git 之外的状态机** —— 无版本控制，撤权不可回滚、不可追溯。
- **无缓存、无向量索引、无搜索索引** —— 因此 §1.5 的"缓存处理"是**不适用**，
  **不得**表述为"缓存已正确失效"。
- **无审计** —— 任何读取/发布都不留痕。
- **提示词自律 ≠ 权限隔离** —— schema 第 8 条是**规范**，不是**机制**；
  本报告不将"模型遵守 schema"计为权限隔离通过。
